# 逐句垂直阅读交互

用户要求：一句原文在上，一句译文在下，全站所有屏宽均保持上下排列。每句译文默认遮挡；用户点击该句下方按钮，才揭晓对应译文。

## 数据

- data/chapters.js 存原文（古籍阅读底本）和旧整章概览。
- data/sentence-parts/01-27.js、28-54.js、55-81.js 存**一条古文对应一条现代译文**的人工翻译数组。
- data/passages.js 负责将原文以。！？；为句界划分，组装稳定 chapter-sentence 编号，并验证逐句数量。
- 不得把同一段摘要填满每个单句，也不可自动把整章意译机械分份伪装成翻译。
- 拼接所有 original 单句必须与该章 original 完全一致，确保无增删。

## 交互

- 结构：古文整句 → 「点击见译」按钮 → 默认隐藏的译文区域。每张卡独立状态。
- 默认所有译文隐藏；新章切换恢复隐藏；页面刷新也应默认隐藏。
- 点击该句仅展开对应译文，再点可收回。提供显式「全部收起」；不自动展开其他句。
- 隐藏时不能只用 blur 或 opacity 假遮挡；真实译文应使用 hidden 属性从布局和可访问树中隐藏。
- 使用 button 与 aria-expanded、aria-controls 维护语义；键盘 Enter/Space 有效。
- 页面无横向原译双列布局，桌面和手机都严格上原文、下译文。

## 验收

检查81章所有句子有译文、源文本拼接完全一致、总句数恒定。抽查1、8、11、38、64、81章的语义对应与打开/关闭状态。
